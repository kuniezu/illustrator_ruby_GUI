# 展示制作向けルビ管理機能 — 初期仕様

更新日: 2026-09-05

## 1. 目的

Adobe Illustrator 上で、展示パネル・教材・博物館解説文などの日本語ルビを、生成して終わりではなく **再編集・再配置・再利用できる形で管理する**。

既存の `Illustrator Ruby GUI.jsx` が持つ対話型入力、縦横組、グループ化、ルビ配置、学習漢字ハイライト等を土台とし、次の課題を解消する。

- 総ルビを一字ずつ入力する負担
- 人名・地名・歴史用語など固有名詞の読みを毎回入力する負担
- 「この箇所だけルビ不要」などの例外指定が再実行で失われる問題
- 本文の移動・改行・文字サイズ変更に伴い、手動調整したルビがずれる問題
- 既存ルビを後から局所的に修正しにくい問題

## 2. 基本原則

1. **自動生成と人間の確認を分離する**。自動読みは候補であり、特に固有名詞・歴史用語は人間が確認できること。
2. **ルビは本文にひもづく管理対象とする**。単なる別テキストオブジェクトとして置くだけにしない。
3. **手動補正は標準配置からの相対差分として保持する**。本文が動いても可能な限り補正を再利用する。
4. **一度決めた読み・不要指定・運用ルールを再利用する**。
5. **元の Illustrator Ruby GUI の動作を壊さず、段階的に拡張する**。
6. **実際の展示原稿・内部資料・ユーザー辞書は公開 GitHub に保存しない**。

## 3. 想定ワークフロー

### 3.1 部分ルビ
1. Illustrator で対象テキストフレームを選択。
2. ツールが既存辞書・自動解析からルビ候補を生成。
3. ユーザーが候補を確認し、必要な語だけ有効化・修正。
4. Illustrator 上へ配置。
5. 後から文字位置周辺を選択して局所編集。

### 3.2 小学生向け等の総ルビ
1. テキストフレームを選択。
2. 「総ルビ」プリセットを選択。
3. 漢字を含む語の読みを自動生成。
4. 辞書一致・一般語・要確認を区別して表示。
5. 誤読候補のみを中心に確認・修正。
6. 一括配置。

総ルビでは、個々の漢字・語を手作業で指定することを前提にしない。

## 4. 読み生成と辞書

### 4.1 優先順位
1. 文書内の明示指定
2. 案件辞書
3. 共通辞書
4. 日本語解析による自動候補
5. 未解決 / 要確認

### 4.2 辞書層
- **共通辞書**: 複数案件で再利用する人名・地名・施設名・歴史用語等。
- **案件辞書**: 特定の企画展・施設・教材等で使う語。
- **文書内指定**: その AI 文書・その出現箇所だけに適用する例外。

### 4.3 辞書に持たせたい情報
最低限:
- 表記
- 読み
- ルビ方針 (`always`, `first`, `normally_off` 等)
- 出典/メモ（任意）

将来候補:
- 別表記・別名
- 人物/地名等のエンティティ単位の関連付け

### 4.4 修正の昇格
読みを修正した際に、適用範囲を選べること。
- この箇所だけ
- この文書
- この案件
- 共通辞書

### 4.5 自動読み生成
形態素解析・辞書等を用い、漢字を含む語の読みを自動提案する。

候補技術例: Sudachi / MeCab + UniDic 等。ただし採用技術は既存 ExtendScript との統合方法、オフライン利用、配布容易性を評価して決める。

## 5. ルビの状態管理

各ルビには少なくとも以下の状態を持たせる。
- `auto`: 自動配置
- `auto_offset`: 自動配置 + 手動相対補正
- `manual`: 完全手動扱い
- `suppressed`: この出現箇所ではルビ不要

`ルビを削除` と `ルビ不要指定` は区別する。`suppressed` は再生成時にも復活させない。

## 6. 本文とのひも付け

絶対座標・単純な文字番号だけに依存しない。

各ルビは可能な範囲で以下を保持し、本文編集後に再解決する。
- 対象テキストフレーム識別子
- 親文字列
- 文字位置
- 前後の短いコンテキスト
- 読み
- 状態
- スタイル
- 相対オフセット

本文先頭への文字追加等で文字位置が変わっても、親文字列と前後文脈を使って再発見できることを目標とする。再解決できない場合は勝手に移動せず「要確認」とする。

## 7. 局所編集

長文全体を毎回 GUI に表示するだけでなく、Illustrator 上でカーソル位置または文字範囲を指定して、その周辺だけ編集できるモードを設ける。

局所編集で必要な操作:
- 読み変更
- ルビ削除
- この箇所ではルビ不要
- サイズ変更
- 横/縦方向の位置微調整
- グループ/熟語単位の変更
- 自動位置へリセット
- 同じ語への適用範囲指定

## 8. ルビ書式

### 8.1 スタイル
書式を「ルビスタイル」としてプリセット化する。

初期候補:
- 展示本文
- キャプション
- 小学生向け総ルビ

ユーザー環境では UD 教科書体を基本ルビフォントとして想定する。ただし特定フォントの存在をコード上の必須条件にはせず、プリセット/設定で変更可能とする。

### 8.2 相対値
可能な限り絶対 pt/mm ではなく親文字に対する比率で保持する。

例:
- rubySize = 親文字サイズの 45%
- gap = 親文字サイズの 8%
- offsetX / offsetY = em 基準または親文字サイズ基準の相対値

本文サイズ変更時にも追従させる。

### 8.3 標準配置 + 差分
最終位置は原則として次で求める。

`親文字から算出した標準位置 + 保存された手動補正`

Illustrator 上でルビを直接ドラッグして修正した場合、可能であれば標準位置との差分を検出し、`auto_offset` として保存する。

## 9. 長い読みへの対応

読みが親文字より長い場合に一律縮小するのではなく、段階的に処理する。
1. 標準サイズ・標準字間
2. トラッキング調整
3. 設定された下限まで段階的縮小
4. 許容する場合は親文字側への進入
5. それでも収まらない場合は要確認

既存 GUI の「調整なし / 変形」を初期実装の土台として利用する。

## 10. プリセット

### 一般展示
- 難読語・固有名詞中心
- 初出のみ等の辞書ルールを利用

### 小学生向け
- 漢字は原則総ルビ
- 自動読み生成
- 要確認候補だけ重点確認

### 学年別
既存の学習漢字データを利用し、指定学年までの既習漢字だけルビを省略するモードも将来候補とする。

## 11. MVP 優先順位

### Phase 0 — 既存コード評価
実装前に Codex が以下を調査する。
- 現行コードのデータフローと責務
- 再編集用メタデータをどこに保持できるか
- Ruby レイヤー/グループ構造
- `createOutline()` 依存部分の制約
- 本文位置再解決の実現可能性
- 自動読み生成を ExtendScript 内で行うか外部処理と分離するか
- 現行コードを最小変更で拡張する案と、分割リファクタリング案

この評価が終わるまでは大規模な書き換えを行わない。

### Phase 1 — 再編集可能なルビデータモデル
- 生成ルビに識別・状態情報を付与
- `suppressed`
- `auto / auto_offset / manual`
- 自動位置へのリセット

### Phase 2 — 辞書
- 共通辞書
- 案件辞書
- 文書内例外
- 修正内容の昇格

### Phase 3 — 自動読み生成 / 総ルビ
- 日本語解析方式決定
- 一括候補生成
- 辞書とのマージ
- 要確認表示

### Phase 4 — 局所編集
- カーソル/文字選択周辺のルビ取得
- 周辺のみ編集
- 不要指定・読み変更・相対位置補正

### Phase 5 — 再配置と追従
- 本文移動・文字サイズ変更への追従
- 改行/テキスト編集後のアンカー再解決
- 解決不能箇所の要確認化

## 12. 開発運用

- このチャット: 仕様検討・レビュー
- GitHub: 正式仕様、Issue、PR、変更履歴
- Codex: 調査・実装・テスト

運用原則:
- `main` は常に動作確認できる状態を保つ。
- 1つの作業に対し原則1ブランチ。
- PR統合後は作業ブランチを長期間残さない。
- 実装前の仕様変更はこの文書または Issue に反映する。
- 実展示原稿、内部資料、実運用辞書、AIファイルは公開リポジトリにコミットしない。

## 13. 非目標（当面）
- Illustrator 本体のネイティブルビ機能の置換
- InDesign 等、他アプリへの同時対応
- クラウド必須の読み生成
- AIによる読みの無確認確定
- 実展示資料そのものの Git 管理

## 14. 技術判断で未確定の項目
Phase 0 の結果で決定する。
- メタデータ保存方法（オブジェクト名、note、文書内データ、別ファイル等）
- テキストフレームの安定識別方法
- 自動読み生成エンジン
- 単一 JSX のまま拡張する範囲
- 外部プロセス/補助アプリを導入するか
- Illustrator バージョン互換性の維持範囲
