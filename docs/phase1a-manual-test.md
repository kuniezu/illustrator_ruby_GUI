# Phase 1A 実機手順：ルビ1件のメタデータ永続化・再読込

## 目的

Issue #4 の最小検証として、既存GUIで生成したルビ1件に再編集用メタデータを書き込み、AIファイルの再オープン後に本文アンカーを安全に再解決できることを確認する。配置計算、既存UI、複数ルビの一括更新はこの検証の対象外とする。

## 手順

1. 短い横書き本文を1つだけ置いた新規AIファイルを作成する。
2. 既存の `Illustrator Ruby GUI.jsx` でルビを1件生成する。
3. 対象ルビにPhase 1Aのメタデータを書き込む。
4. AIファイルを保存して閉じる。
5. Illustratorを再起動するか、保存したAIファイルを再度開く。
6. スクリプトを再実行し、対象ルビのメタデータを再読込できることを確認する。
7. 本文を変更していない状態で、`baseText`、旧位置、前後コンテキストから本文候補が一意に解決されることを確認する。
8. 同じ本文文字列を追加し、候補が複数になる状態を作る。`needsReview` 相当の要確認として扱われ、ルビが勝手に移動・更新されないことを確認する。
9. 縦書き本文でも保存・再オープン・メタデータ再読込ができることを確認する（位置計算の改善は行わない）。

## 記録項目

- Illustratorのバージョン
- OS（macOS / Windows）
- 使用フォント（UD教科書体を使った場合も、必須依存かどうかを分けて記録）
- `PageItem.name` と `PageItem.note` の書き込み結果
- 保存して再オープンした後の読み出し結果
- ルビを複製した場合のメタデータとアンカー解決結果
- ルビが生成グループ内にある状態での読み出し結果
- 横書き・縦書きそれぞれの結果

## 合格条件

- `name` / `note` の利用可否を実機で検出でき、書き込み後および再オープン後の値を記録できる。
- 本文アンカーが一意に解決できる場合だけ復元対象になる。
- 候補が0件または複数件の場合、`needsReview` として停止し、自動移動・自動更新しない。
- メタデータのない既存AIファイルと既存ルビは従来どおり利用できる。
- メタデータが壊れている場合も、既存オブジェクトを変更しない。

## 今回は検証しない項目

`suppressed`、手動オフセットの差分検出・ドラッグ追跡、回転・拡大縮小されたテキストフレームの座標対応、辞書、Sudachi / MeCab、総ルビ、文字カーソルによる局所編集、複数テキストフレーム、ルビの自動更新・削除、大規模リファクタリングはPhase 1Aの対象外である。
