# Phase 1B 実機手順：本文と生成ルビの一体移動

## 目的

Issue #6 の対象である、単一TextFrameとその生成ルビを同じラッパーGroupItem配下に置き、Illustrator上で一体として選択・移動できることを確認する。本文編集後の自動再配置や複雑な階層への対応は対象外とする。

## 手順

1. 短い横書き本文を1つだけ置いた新規AIファイルを作成する。
2. 既存の `Illustrator Ruby GUI.jsx` でルビを1件生成する。
3. 本文とルビが1つのラッパーGroupItemとして選択できることを確認する。
4. ラッパーグループを移動し、本文とルビが一緒に移動し、相対位置が変わらないことを確認する。
5. AIファイルを保存して閉じ、再オープン後もラッパー構造が保持されることを確認する。
6. 保存済みAIファイルを閉じて再オープンし、`rubyPair_<frameId>` ラッパーを選択してスクリプトを再実行する。
7. ラッパー直下の本文TextFrameが一意に解決され、既存ルビメタデータを読み込んで再編集フローに入れることを確認する。
8. 生成ルビ側TextFrameを本文と誤認せず、`rubyPair_` 構造またはframeIdで一意に解決できないGroupItemは明示的に停止することを確認する。
9. 縦書き本文でも同じ移動・保存・再読込を確認する。
10. 既存GroupItem内、ロック・非表示、連結テキスト、クリッピングマスク等の対象では、勝手に再親子化せず従来構造を維持することを確認する。

## 記録項目

- Illustratorのバージョン
- OS（macOS / Windows）
- 本文の元の親（Layer / 単純なGroupItem）
- ラッパーGroupItemの生成結果と移動結果
- 保存・再オープン後のグループ構造
- 再実行時のメタデータ読込結果
- ラッパー選択から本文を一意に解決できた結果
- 横書き・縦書きの結果
- 安全側に停止した複雑な階層の条件

## 合格条件

- 本文を複製せず、元のTextFrameとルビ群が同じラッパーGroupItem配下に入る。
- ラッパーの移動・拡大縮小で本文とルビの相対位置が崩れない。
- 保存・再オープン後も構造とPhase 1Aのメタデータ読込が成立する。
- ラッパー選択後も本文TextFrameを安全に一意解決し、再編集できる。
- 複雑な階層や安全条件違反時に自動再親子化しない。

## 今回は検証しない項目

本文編集後の自動再配置、手動オフセット差分の検出、連結テキストの対応、クリッピングマスク内部の完全対応、複数TextFrameの一括処理、レビューUI刷新は対象外とする。
