# 00 — Product Goals

更新日: 2026-09-05
状態: Draft 0.1 / user + Sol consensus

## 1. 目標

Adobe Illustrator上で、展示パネル、博物館解説文、教材などの日本語長文について、ルビを「一度配置して終わり」にせず、生成・確認・修正・再編集・再配置できるルビ管理ツールを作る。

中心となる考え方は、**ルビTextFrameではなく、本文にひもづく意味データを正本として扱うこと**である。

## 2. 主な利用場面

- 展示パネルや解説文の数十〜数百文字以上の本文
- 固有名詞、地名、専門語などを含む文章
- 一般展示の部分ルビ
- 小学生向け等の総ルビ
- 後日AIファイルを再オープンして読みや配置を修正する作業
- 本文の移動、文字サイズ変更、組み直し、行送り変更後の再配置

## 3. 目指すユーザー体験

現行の「全文字を入力欄へ展開し、実行ボタンでルビを新規生成する」ことを主役にしない。

主な流れは次を想定する。

1. Illustrator上で本文フレームまたは文字範囲を選ぶ。
2. ツールがルビ対象となる語候補を抽出する。
3. 読み候補・辞書一致・要確認を提示する。
4. ユーザーが読み、ルビ有無、語境界等を確認・修正する。
5. ルビを描画する。
6. 後日、同じAIを開いて既存ルビを再取得し、局所的に再編集する。
7. 本文や組版が変わったら、既存データを可能な限り再解決し、曖昧な箇所だけ要確認にする。

長文では「全部を最初から見直す」より、**要確認箇所を順に校正するレビュー型ワークフロー**を重視する。

## 4. 正本となるデータ

ルビの意味情報を `RubyAnnotation` のようなドメインデータとして保持する。

概念例:

```text
RubyAnnotation
- annotationId
- sourceFrameId
- baseText
- sourceAnchor
- beforeContext
- afterContext
- reading
- grouping
- state
- stylePreset
- offsetX / offsetY
- splitHints
```

Illustrator上に生成されるルビTextFrameやグループは、このAnnotationを描画した結果であり、正本ではない。

## 5. 基本原則

- 基本単位は1文字ではなく語・語句。
- 自動処理は候補生成であり、人間が確認・修正できる。
- 一度決めた読み、抑制、手動語境界、分割ヒントを再利用する。
- 再実行しても生成物が増殖しない。
- native Illustrator UUIDを永続IDの正本として信用しない。
- 本文との対応が曖昧なら、推測して自動更新せず要確認にする。
- GUI、Rubyレイヤー、wrapper方式など現行の実装方式を維持すること自体は目的にしない。
- 現行コードやupstreamの有用なアルゴリズムは参考にするが、必要なら実装を書き直す。

## 6. 当面の非目標

- IME native API連携をMVP必須としない。
- クラウド必須の読み生成にしない。
- AI/形態素解析の読みを無確認で確定しない。
- InDesign等への同時展開はしない。
- 実展示原稿や案件辞書を公開GitHubへ置かない。
- 現行PR #8を完成させること自体をv2設計の目的にしない。
