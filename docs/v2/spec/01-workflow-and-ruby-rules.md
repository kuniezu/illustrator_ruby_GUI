# 01 — Workflow and Ruby Unit Rules

更新日: 2026-09-05
状態: Draft 0.1 / user + Sol consensus

## 1. ルビの基本単位

ルビ管理の基本単位は1文字ではなく、語・語句とする。

例:

```text
日本庭園 / にほんていえん
一張羅   / いっちょうら
```

常時、各漢字に個別readingを割り当てる方式は採らない。

## 2. 自動的な語候補

初期の候補抽出では、連続する漢字列を基本的な語候補として扱う。

- 漢字列の途中にひらがなが入れば原則としてそこで分割する。
- 句読点、空白等は境界として扱う。
- 括弧で囲まれた漢字列・語句は、外側から独立したまとまり候補として扱う。
- 括弧内部にひらがな等の境界があれば、原則として通常の分割則を適用する。
- 自動判定された語境界は、ユーザーが任意に `split` / `merge` できる。
- ユーザーが明示した `manual split` / `manual merge` は保存し、再解析で勝手に上書きしない。

自動形態素解析の語境界をそのまま正解とはしない。展示制作上のルビ単位を優先する。

## 3. 論理的な語と描画単位

**意味上・編集上の語**と、**Illustrator上で実際に描画するルビ単位**を分けて考える。

通常:

```text
Logical Ruby:
日本庭園 / にほんていえん
```

Illustratorの組版で行末をまたぎ、見た目が次のようになった場合:

```text
日本
庭園
```

意味上は `日本庭園 / にほんていえん` の1語として保持してよいが、描画上は次の2セグメントにする。

```text
日本 / にほん
庭園 / ていえん
```

同様に:

```text
一張羅 / いっちょうら
```

が

```text
一張
羅
```

と折れた場合は、描画上:

```text
一張 / いっちょう
羅   / ら
```

としたい。

## 4. 行折り返し時の読み分割

全文字に対するreading alignmentは常時保持しない。

語が実際に行をまたいだときだけ、本文側の分割位置を検出し、初回はユーザーへ読みの分割位置を確認する。

例:

```text
本文: 一張 | 羅
読み: いっちょう | ら
```

保存するのは必要な境界だけの `split hint` とする。

概念例:

```text
splitHint
- baseBoundaryAfter: 2
- readingBoundaryAfter: 5
```

同じ本文境界で再び折り返した場合は保存済みhintを再利用する。一行に戻った場合はhintを無視し、元の1語1ルビとして描画する。別の位置で折れた場合は、その新しい境界についてのみ確認する。

## 5. 明示改行と自動折り返し

- Illustratorの自動折り返しは、論理的な語そのものを恒久的に分割する理由にはしない。ただし描画上の分割境界にはする。
- 本文に明示的な改行文字が存在する場合は、その時点では強い境界として扱う。
- 後で明示改行が削除され、前後の漢字列が連続した場合は再tokenizeし、1語候補へ戻る可能性を認める。
- 既存の読み・確認状態を引き継げる場合は候補として引き継ぎ、曖昧ならreviewへ送る。

## 6. 長文レビューの操作単位

長文作業では、全文字の入力欄を主UIにしない。

想定操作:

- 現在選択中の語を見る
- 読みを確認・変更する
- ルビあり／なしを変更する
- 語をsplit / mergeする
- 次の要確認へ進む
- 前の要確認へ戻る
- 文書全体のunresolved / review一覧を見る
- 必要なら位置を微調整する

全文の一覧表示は補助機能であり、局所編集・レビューを主役とする。
