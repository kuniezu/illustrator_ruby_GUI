## 3. 最初にcross-realm仮説を最小再現する

**Node VMに合わせるためだけにproductionのES3-safe serializerを変更しない。**

一方、調査の結果productionでもrealm-independent serializerが必要だと証明された場合は、その根拠を03へ書いたうえで最小production修正を許可する。

- 02 / 03 / checklist / catalogを必要に応じて更新
- 40桁implementation SHA確定
- remoteへpush
- remote HEAD確認

### BLOCKEDでSTOP

次の場合のみ:

- Illustrator実機でしか判定できないhost behaviorに到達
- production仕様変更の是非をsupervisor判断なしに決められない
- ownership/source preservationを危険にする修正が必要
- current changesのprovenanceが不明で安全に継続できない
- repeated harness failureを最小再現しても原因分類不能

BLOCKED時は必ず:

- failing test名
- exact error/stack
- 最小再現結果
- production bug / harness mismatch / expectation bug の現時点分類
- 変更中ファイル
- `git diff --check`
- local HEAD / remote HEAD

を報告する。

単に「VM差異」「dirtyなので停止」だけでは終わらず、上記0の手順で安全に継続可能なら継続する。
