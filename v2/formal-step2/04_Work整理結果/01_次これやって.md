## 実機で確認された失敗

長文AreaTextで `再編集` が実際の行境界をまたぎ、UI一覧では `[ready]` なのに保存時plannerが `split-hint-required` を返した。

## supervisor側の再監査結果

単発の `split-hint-required` だけ直さないこと。

`workflow.js` の `occurrenceStatus()` は現在、`unsupported / enabled / readingConfirmed / reading` だけで `ready` を決める。一方、実render可否は `orchestration.js` / `segments.js` で初めて判定され、少なくとも次のplanner-only unresolvedがあり得る。

- `manual-placement`

したがって今回の本質は「入力状態のready」と「render可能状態」を同一ラベルとして扱っていること。UI/diagnosticsがrender未完了を成功と誤認させないよう、同クラスの状態ずれをまとめて閉じる。

## 今回やること

### 1. render readinessを入力readinessから分離

- `occurrenceStatus()` の意味を不用意に拡張せず、必要なら `input-ready` 相当として扱う。
- 保存/plan後の結果には、occurrence / annotationごとのrender status と reason を保持・UI反映できる最小経路を追加する。
- plannerがunresolvedならUI一覧で単純な `[ready]` のままにしない。
- suppressed / unsupported / reading-unconfirmed の既存意味は壊さない。

### 2. `split-hint-required` を実用workflowへ接続

- 行をまたぐoccurrenceで `split-hint-required` が出た場合、対象occurrenceを特定できること。
- plannerが返したbase側の実行境界を、source-relative / occurrence-local boundaryとしてUIへ渡せるようにする。
- 既存の「局所分割」機構へ自然に接続する。reading境界を勝手に比例推測しない。
- 現在のlong-textモデルでは局所分割後に各child readingをユーザー確認させる方針を維持してよい。
- `FormalSegments` の「複数行readingを無断で推測分割しない」契約は緩めない。

### 3. misleading success表示を修正

- BridgeTalk/永続化自体の成功とrender成功を区別する。
- render planがunresolved/failedなのに、ユーザー向けdebug/statusで単独の `success` が成功描画を意味するように見えないこと。
- transport/persistence成功を残す必要があるなら `persisted` / `transport-success` 等の意味が分かる表現に分離するか、少なくともrender outcomeと同じレコードで明示する。
- 「読み情報は保存できたがrubyは未描画」という既存の安全な永続化挙動は維持する。

### 4. 同型状態ずれを回帰化

最低限、次をテストする。

- reading確認済みで1行内ならrender-ready / complete。
- reading確認済みでも実行境界をまたげば `split-hint-required` となり、UI/render statusが単純なreadyを名乗らない。
- `split-hint-required` の対象occurrenceとbase boundaryがUI/action層まで届く。
- 局所分割後、各childがreading再確認を要求し、誤った自動reading分割をしない。
- `split-hint-stale` / `split-hint-boundary-mismatch` など同クラスのplanner unresolvedも「ready表示固定」にならない。
- persistence成功 + render unresolvedを、render成功として表示しない。
- suppressed / re-enabled / review queue既存挙動を壊さない。

既存テストだけでなく、今回の失敗を再現する「長文中の漢字occurrenceがAreaTextの実行境界をまたぐ」fixtureをpure/integrationで追加する。
