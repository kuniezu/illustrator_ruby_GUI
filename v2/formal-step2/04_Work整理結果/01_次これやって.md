## audit B: complete production route

以下を1本の状態遷移として追跡する。

`source/reopen → input readiness → projection → observation → planner → durable bundle → BridgeTalk callback → palette → split/review → native prepare/verify/activate → retirement/cleanup → terminal evidence → reopen`

各区間で確認:

### data ownership / identity
- source UUID + document path authority。
- occurrenceId / annotationId / logicalSegmentId / physicalIdの責務分離。
- split lineageをnative ownership IDの代替に使っていない。
- split→render→reopenで旧physical outputが重複しない。
- source/unmanagedをretireしない。

### status algebra
- input ready ≠ planner complete ≠ render pending ≠ terminal complete。
- hidden-confirmedはno-output complete相当だがvisible siblingをblockしない。
- unresolved/failedはaggregate blocker。
- terminal visible completeはnative success後のみ。
- reopen後もdurable evidenceがUIで同じ意味になる。

### async / callback
- one save → one `send=true` display。
- send(false)/timeout/onError → transport-uncertain, blind retry禁止。
- authoritative persisted noteがcallback statusより優先。
- late callback/duplicate callbackでUI stateを巻き戻さない。

### split/review
- required split → child reading再確認 → save → complete。
- required split childrenのmerge拒否。
- ordinary/manual split/mergeは必要以上に壊していない。
- review queue、前/次未解決、suppression/re-enable、selection refreshが整合。

### lifecycle/recovery
- begin → prepare → verify → activate → retire/cleanup → finish。
- activation前failureはabort/cleanup、activation後failureはrollbackしない。
- recoveryがunfinished stateをbounded convergeしてから次save。
- duplicate/missing identityはfail-closed。
