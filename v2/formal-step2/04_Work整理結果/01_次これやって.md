## blocker A: guarded mergeの可否がtarget completeではなくaggregate completeにも依存している

現行UI helper `currentMergePlan()` はtarget annotationIdを正しく特定するよう改善されたが、最後に:

```js
if(projected.plan.status!=="complete" ||
   matches.length!==1 ||
   matches[0].status!=="complete" ||
   !matches[0].decision ||
   matches[0].decision.status!=="complete")
    fail("merge-would-restore-split-blocker");
```

としている。

`FormalLongText.mergeAdjacentWithPlan()` も:

```js
if(!plan || plan.status!=="complete" || !plan.results)
    fail("merge-current-plan-not-complete");
```

とaggregate `plan.status===complete` を要求する。

しかし今回のguard revalidationが証明したいのは、**選択中のmerged targetがcurrent geometryでsplit不要か**である。

production fixtureでは、targetとは無関係のsiblingが:

- reading未確認
- unresolved
- failed
- review待ち

などでaggregateをunresolved/failedにしていても、target item自体はcurrent observation上 `complete` になり得る。

この場合、現在の実装はtarget completeを正しく見つけてもaggregate noncompleteだけでmergeを拒否する。

これは以前から明示している:

- item-level vs aggregate-level state
- horizontal sibling propagation
- false-positive blocker classification

の混同。

### expected semantic

Guarded merge decisionはlocal edit decisionであり、target itemのcurrent proofを使う。

- target resultが一意に存在
- target result `status=complete`
- target `decision.status=complete`
- targetがvisible merged candidateとしてidentity一致

なら、**unrelated siblingのunresolved/failedだけを理由にguarded mergeを禁止しない**。

ただし:

- observation自体がfailed/unavailableでtarget resultを安全に作れない → fail-closed
- target result missing/duplicate/unresolved/failed/hidden → reject
- target decision noncomplete → reject

aggregate statusはsave/render transaction全体の可否には使うが、local merge guardのtarget-current-proofと同一視しない。

### repair direction

- `currentMergePlan()` はprojected plan全体からtarget itemをidentityで一意に解決し、そのtarget itemのsemanticだけをguard判定へ返す/検証する。
- `mergeAdjacentWithPlan()` もaggregate `plan.status===complete` を必須条件にしない。target result identity + status + decisionを検証する。
- target lookupをduplicated UI/model logicにしすぎない。可能ならpure helper化して1契約にする。
- aggregate planner semantics (`failed > unresolved > complete`) 自体は変更しない。
- normal save/renderではaggregate blockerを従来どおり尊重する。
