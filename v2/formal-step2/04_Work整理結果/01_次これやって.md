## blocker A: reading-unconfirmed occurrence が whole-frame aggregate blockerから消える

現行 `FormalMultiProjection.project()` は `eligible(occurrence)` がfalseのoccurrenceをannotationへ投影しない。

`eligible` は:

```js
return !occurrence.unsupported && occurrence.enabled && occurrence.readingConfirmed && occurrence.reading.length > 0;
```

一方 `FormalMultiRenderer.plan()` は occurrence ごとに projected annotation を探し、

```js
if (!annotation || !annotation.enabled) {
    plans.push({status:"complete", suppressed:true, ...});
    continue;
}
```

としている。

従って enabled=true だが reading未確認/空reading のoccurrenceは:

1. projectionでannotationが生成されない。
2. renderer側では「annotationが無い」ことを suppression と区別できない。
3. `status=complete / suppressed=true` と誤分類される。
4. UI `occurrenceStatus()` では `unresolved` なのに、save/render aggregateではblockerから消え得る。

これはstatus algebraの矛盾。

### required semantic

少なくとも次を明確に分けること。

- `enabled=false` → suppressed/no-output/nonblocking。
- `enabled=true && reading未確認/empty` → unresolved blocker、native candidateなし。
- `unsupported` →既存契約を確認し、suppressedと同一視しない。現行UI/既存tests/known-failure catalogに従って明示的semanticを維持する。
- eligible confirmed occurrence → plannerへ渡す。

「annotation missing = suppressed」というshortcutは禁止。

projectionを必ず未確認annotationまで生成する設計に変える必要はない。occurrence stateをrendererが直接見て分類する最小修正でもよい。既存projection責務とannotation planner契約を確認して最小変更を選ぶ。
