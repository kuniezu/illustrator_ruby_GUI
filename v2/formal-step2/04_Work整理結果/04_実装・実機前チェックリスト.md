# 実装・実機前チェックリスト

この文書は、過去に実際に発生した見落としを再発させないための共有チェックリスト。

- Luna/Codex/Work worker: **実装開始前** と **完了報告前** に確認する。
- ChatGPT supervisor: **remote review時** と **ユーザー実機を依頼する直前** に確認する。
- ユーザー: 必要に応じて内容を確認できるが、チェック作業の責任をユーザーへ移さない。

チェックリストは `known-failure-regression-catalog.md` の代替ではない。catalogはコード不具合の回帰、こちらは実装・レビュー・運用上の見落とし防止を目的とする。

## A. worker 実装開始前

### A1. 最新remote / handoff

- [ ] `git fetch origin` 済み。
- [ ] worktree clean を確認した。
- [ ] divergence がなく、必要なら `git pull --ff-only` で最新remoteへ同期した。
- [ ] 最新の `01_次これやって.md` を **同期後に** 読んだ。
- [ ] dispatch_id / state / target_branch を確認した。
- [ ] Issue #14、チャット履歴、古い01を実行指示として使っていない。
- [ ] `base_code_head` が現在branchの祖先であることを確認した。dispatch文書自身を更新するcontrol-plane commitのため、HEAD完全一致を要求していない。

### A2. 既存知見 / precedent

- [ ] 変更対象API・状態遷移・UI状態についてrepo内検索した。
- [ ] 旧実装 `Illustrator Ruby GUI.jsx` に同じIllustrator DOM操作または同等のライフサイクルがないか確認した。
- [ ] `known-failure-regression-catalog.md` に同型事故がないか確認した。
- [ ] Issue #14の既知実機事故に同型がないか必要な範囲で確認した。
- [ ] 既存precedentと違う実装をする場合、その理由と回帰テストを残した。

### A3. Illustrator / ExtendScript固有

- [ ] `TextFrame.kind` を後からAreaTextへ安全に変えられる前提を置いていない。
- [ ] `TextFrame.width` / `source.width` setterだけでactual AreaText reflowを証明していない。
- [ ] `createOutline()` が元TextFrame/duplicateをconsume・invalidateし得ることを考慮した。
- [ ] temporary DOM objectの所有権とcleanup対象を二重解放していない。
- [ ] `createOutline()` の回数を無自覚に増やしていない。増やす場合は旧実装の「1回outlineを共有」知見との差を確認した。
- [ ] production/diagnosticにES3非互換Array API等を持ち込んでいない。
- [ ] Node test成功だけをIllustrator runtime互換性の証拠にしていない。

### A4. UI状態とrender状態

- [ ] input readiness（reading確認済み等）とrender readinessを混同していない。
- [ ] UIの `ready` / `success` 表示がplanner/renderの実状態と一致する。
- [ ] planner-only unresolved（例: `manual-placement`, source resolve unresolved, `annotation-line-intersection-unavailable`, `split-hint-required`, `split-hint-stale`, `split-hint-boundary-mismatch`, observation unresolved）がUIで単純なreadyに見えない。
- [ ] transport/persistence成功とrender成功を同じ `success` として見せていない。
- [ ] unresolved理由から、ユーザーが取れる既存UI操作へ接続できる場合は接続した。

### A5. split / reading

- [ ] 複数行Annotationのreadingを比例配分・推測分割していない。
- [ ] `split-hint-required` では実base境界を保持している。
- [ ] stale/mismatch hintを黙って採用しない。
- [ ] 局所split後はchild readingを再確認させる既存契約を維持している。

### A6. persistence / ownership / async

- [ ] source document identityとsource TextFrame UUIDを保守的に扱っている。
- [ ] BridgeTalk callback時に現在selectionだけを再解決していない。
- [ ] timeout / send(false) / result / error / callback lifetimeを既存契約どおり扱っている。
- [ ] previous manifestをsource note overwrite前に読んでいる。
- [ ] copy-on-write: prepare → verify → activate → retire/cleanup → finish の順序を壊していない。
- [ ] activation後cleanup失敗をrollback扱いしていない。
- [ ] source / unmanaged objectをretire対象にしていない。
- [ ] same-logical replacementとtrue logical removalを混同していない。
- [ ] palette restart後もphysical ID collisionを起こさない。

## D. ユーザー実機を依頼する直前 — PRE-RUNTIME CHECK

以下をすべて確認できるまで、ユーザーへ実機実行を依頼しない。

- [ ] **PRE-RUNTIME CHECK: code path reviewed** — 実機で通す実際のproduction pathを最後まで追った。
- [ ] **PRE-RUNTIME CHECK: scenario supported** — 依頼するfixture/操作が、コード上そもそもunresolved必須の未対応ケースではない。
- [ ] **PRE-RUNTIME CHECK: UI truthfulness** — ready/success表示とplanner/render結果が食い違わない。
- [ ] **PRE-RUNTIME CHECK: prior failures replayed** — 今回に関係する既知失敗が自動回帰で落ちることを確認した。
- [ ] **PRE-RUNTIME CHECK: DOM precedent** — 使用するIllustrator DOM操作を旧実装/既存成功パターンと比較した。
- [ ] **PRE-RUNTIME CHECK: ES3** — runtime pathがExtendScript compatibility gate対象である。
- [ ] **PRE-RUNTIME CHECK: identity/async** — document/source identity、BridgeTalk、callback raceに既知の穴がない。
- [ ] **PRE-RUNTIME CHECK: lifecycle** — copy-on-write/retirement/cleanup/duplicate ownershipを壊していない。
- [ ] **PRE-RUNTIME CHECK: test purpose** — 実機で何を証明し、何は証明しないかを限定した。
- [ ] **PRE-RUNTIME CHECK: stop condition** — 失敗時に追加操作を重ねず停止できる観測点がある。

全項目確認後のみ、supervisorはチャットで明示的に

`PRE-RUNTIME CHECK: PASS`

と宣言して実機手順を案内する。

## E. 過去に実際に起こしたレビュー・運用ミス一覧

この節は、新しいミスが見つかったら追記する。

1. Gate C既知のAreaText reflow制約をGate D fixtureで再度踏んだ。
2. `TextFrame.kind`を後変更できる前提を一度採用した。
3. Nodeで通る `Array#indexOf` 等をExtendScript runtimeへ持ち込んだ。
4. diagnostic JSXをcompatibility gate外に置いて同じES3事故を再発させた。
5. BridgeTalkのsend/timeout/target/UUID identityを確認せずruntime GOを出した。
6. copy-on-write / retirement契約が既知なのにpractical pathの順序違反を見逃した。
7. same-logical replacementとlogical removalの区別を後追いで修正した。
8. palette restart時physical ID collisionを後追いで修正した。
9. `createOutline()`成功後duplicateがconsumeされる既存lifecycleを見落とした。
10. 旧実装にあった「outlineを1回だけ共有（クラッシュ防止）」知見をruntime前監査で十分に重視しなかった。
11. input-readyとrender-readyを混同し、`再編集`が実行境界をまたぐのにUI `[ready]` のままruntimeへ進めた。
12. persistence/transport `success` とrender unresolvedをユーザー表示上区別しなかった。
13. `01_次これやって.md` にユーザー実機手順まで書き、worker指示とユーザー操作を混在させた。
14. worker開始時にremote syncを必須化せず、古い01を読む可能性を作った。
15. dispatch文書自身のcommitでHEADが進むのに、01へ「更新前HEADとの完全一致」を要求する自己矛盾した運用を作った。
16. remoteにworker完了commitがない時点で、worker側だけの問題と早計に切り分けた。

新しい事故が判明した場合は、単に番号を増やすだけでなく、A〜Dのどこかに**再発防止チェック項目**を追加する。
